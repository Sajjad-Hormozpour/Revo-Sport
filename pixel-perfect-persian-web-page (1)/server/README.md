# سرور دیتابیس مرکزی Revo sport

بدون این سرور، اپ هر کاربر را روی مرورگر خودش ذخیره می‌کند (دیتابیس جدا برای هر دستگاه).
با اجرای این سرور، **یک دیتابیس مشترک** برای همه وجود دارد و اپ خودش تشخیص می‌دهد و به آن وصل می‌شود.

## اجرا

```bash
npm install
npm run build          # ساخت اپ در پوشه dist
node server/index.mjs  # اجرای سرور (اپ + دیتابیس) روی پورت 8787
```

بعد آدرس `http://localhost:8787` را باز کن. Node نسخه ۱۸ یا بالاتر لازم است و **هیچ پکیج اضافه‌ای نیاز نیست**.

## تنظیمات (متغیرهای محیطی)

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `PORT` | `8787` | پورت سرور |
| `DATA_DIR` | `server/data` | محل دیتابیس، فایل‌ها و پشتیبان‌ها (**حتماً روی دیسک پایدار باشد**) |
| `ADMIN_EMAIL` | — | کسی که با این ایمیل ثبت‌نام کند «ادمین» می‌شود |
| `TRUST_PROXY` | — | اگر پشت Nginx/Cloudflare هستی مقدار `1` بگذار (برای محدودیت درست تعداد تلاش ورود) |
| `RESET_WEBHOOK_URL` | — | آدرسی که کد بازیابی رمز را به‌صورت JSON (`email`, `code`, `name`) می‌گیرد تا ایمیل/پیامک بفرستی |
| `KAVENEGAR_API_KEY` | — | کلید سرویس کاوه‌نگار برای ارسال واقعی کد موبایل |
| `KAVENEGAR_TEMPLATE` | `revosportverify` | نام الگوی تأیید ثبت‌شده در پنل کاوه‌نگار |
| `SMS_WEBHOOK_URL` | — | جایگزین کاوه‌نگار: سرویس پیامک خودت؛ دریافت‌کننده JSON شامل `phone`, `code`, `purpose`, `message` |
| `SMS_WEBHOOK_SECRET` | — | توکن Bearer برای فراخوانی امن `SMS_WEBHOOK_URL` |
| `OTP_DEV_MODE` | خاموش | فقط برای تست توسعه همراه با `NODE_ENV` غیر production؛ کد در پاسخ نمایشی و لاگ سرور دیده می‌شود |
| `CORS_ORIGIN` | — | فقط اگر اپ و سرور روی دو دامنه جدا هستند |
| `DIST_DIR` | `../dist` | مسیر اپ ساخته‌شده |

اگر اپ و API روی دو دامنه جدا باشند، هنگام ساخت اپ مقدار `VITE_API_URL` را بگذار.

## چه چیزی کجا ذخیره می‌شود

- `DATA_DIR/db.json` — دیتابیس مشترک (کاربران، شاگردان، برنامه‌ها، تمرین‌ها، پیام‌ها، پرداخت‌ها و…)
- `DATA_DIR/media/` — عکس و ویدیوهای آپلودشده مربی‌ها
- `DATA_DIR/backups/` — پشتیبان روزانهٔ خودکار (۱۴ نسخهٔ آخر)

## امنیت و جداسازی دسترسی

- رمزها با `scrypt` هش می‌شوند؛ هیچ‌وقت رمز ساده ذخیره یا برگردانده نمی‌شود.
- ورود و ثبت‌نام به **شماره موبایل ۱۱ رقمی** نیاز دارند. ابتدا کد یک‌بارمصرف سه‌دقیقه‌ای ارسال می‌شود، سپس بعد از تأیید آن حساب یا نشست ساخته می‌شود؛ endpoint قدیمی ورود بدون OTP غیرفعال است.
- برای ورود عملی روی سرور باید `KAVENEGAR_API_KEY` و الگوی تأیید یا `SMS_WEBHOOK_URL` را تنظیم کنی. بدون سرویس پیامک، سرور اجازه صدور کد واقعی/ورود را نمی‌دهد.
- حساب‌های قدیمی که قبلاً موبایل نداشتند، پس از تأیید کد روی شماره‌ای که با ایمیل و رمز خودشان وارد کرده‌اند، به همان شماره متصل می‌شوند.
- هر مربی **فقط شاگردان خودش** و هر شاگرد **فقط اطلاعات خودش و مربی‌اش** را از سرور می‌گیرد (نه فقط مخفی در ظاهر اپ).
- شاگرد نمی‌تواند برنامه، پلن یا اطلاعات مربی را تغییر بدهد؛ مربی نمی‌تواند شاگرد مربی دیگر را ببیند یا تغییر بدهد.
- تلاش‌های ورود و بازیابی رمز محدود شده‌اند.
- **حتماً پشت HTTPS اجرا کن** (Nginx، Caddy، Cloudflare و…). روی HTTP ساده رمزها بدون رمزنگاری رد و بدل می‌شود.

## بازیابی رمز

کد ۶ رقمی روی سرور ساخته و در لاگ سرور چاپ می‌شود. برای ارسال واقعی ایمیل/پیامک،
`RESET_WEBHOOK_URL` را به سرویس خودت وصل کن.

## اجرا با Docker

```bash
docker build -t revo-sport .
docker run -d -p 8787:8787 -v revo-data:/data -e ADMIN_EMAIL=you@example.com revo-sport
```

## انتقال داده‌های قدیمیِ یک مرورگر

قبل از استفاده از سرور، در نسخهٔ قدیمی: تنظیمات ← «دانلود خروجی». بعد روی سرور با همان حساب مربی ثبت‌نام کن و
در تنظیمات، فایل را «بازیابی» کن؛ شاگردان، برنامه‌ها و تمرین‌ها به دیتابیس مرکزی اضافه می‌شوند.

## محدودیت‌های فعلی

- دیتابیس یک فایل JSON است و برای چند ده تا چند صد کاربر مناسب است؛ برای مقیاس بزرگ باید به PostgreSQL منتقل شود.
- پرداخت اشتراک هنوز شبیه‌سازی‌شده است و به درگاه واقعی بانک وصل نیست.
- هماهنگی بین دستگاه‌ها هر ~۳ ثانیه انجام می‌شود (نه لحظه‌ای).
